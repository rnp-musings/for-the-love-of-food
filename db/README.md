# Database

Postgres schema, importer and example queries. Nothing here is used by the live site yet: the static site still reads `/content` directly.

| File | Purpose |
|---|---|
| `schema.ts` | Drizzle schema: places, dishes, recipes, ingredients, festivals, sources, the spice library, review log |
| `migrations/` | SQL generated by `drizzle-kit` (`0000_init`) plus hand-written extras (`0001_search_extras`: trigram search, `updated_at` triggers) |
| `client.ts` | Opens real Postgres (`DATABASE_URL`) or an embedded Postgres (PGlite) |
| `import.ts` | Loads `/content/*.json` into the database |
| `queries.ts` | `searchDishes()` (all site filters) and `dishesUsingSpice()` |
| `smoke.ts` | End-to-end test on an in-memory database |

## Commands

```bash
npm run db:smoke                      # no setup needed; runs everything against embedded Postgres
npm run db:import -- --pglite         # try an import into a throw-away database
npm run db:import -- --pglite ./.pgdata   # same, persisted locally

# real database (Supabase, Neon, local):
export DATABASE_URL='postgres://...'
npm run db:migrate
npm run db:import -- --dry-run        # runs in a transaction and rolls back
npm run db:import

# after editing db/schema.ts:
npm run db:generate                   # writes a new SQL migration; review it before committing
```

## How content and database fit together

- JSON in git stays the source for content. The importer upserts by id and replaces child rows, so it is safe to re-run.
- `review_status` set in the database is **preserved** on re-import, so a reviewer's work is not undone. Pass `--overwrite-review` to take the JSON value instead.
- The `sources.checked` flag is likewise only ever raised by the importer, never lowered.
- Records deleted from JSON are reported as orphans, not deleted.
- `scripts/validate.py` runs first and must pass (skip with `--skip-validate`).

## Spice library

Spices are ingredients in the `herb-spice` category. The importer creates an empty profile row in `spices` for each, so every spice already has a page to fill in. To add content, create `content/spices.json` (schema: `schemas/spice.schema.json`) and `content/blends.json` (`schemas/blend.schema.json`), then run `python3 scripts/validate.py` and the import. A spice `id` must equal its ingredient id. Fields: scientific name, part used, heat level (0 to 5) and Scoville units, flavour notes, aroma, history, storage, buying tips, origin countries (native / major producer / historic trade) and substitutes. Blends list component spices with a free-text proportion note, because blends vary by cook. "Dishes that use this spice" comes from the existing recipes via the `dish_ingredients` view.
